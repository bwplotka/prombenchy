# verify-metrics

`verify-metrics` is an acceptance verification tool that assesses the 1 series per metric type generated by the shared [Avalanche](https://github.com/prometheus-community/avalanche) target (`core/avalanche`) over a configurable time window (`-window`).

It supports verifying metrics via:
1. **PromQL** (`-mode=promql`): Queries Google Managed Prometheus PromQL API or a local/remote Prometheus instance (`/api/v1/query`) using `count_over_time`, `min_over_time`, and `max_over_time` over `[<window>]`.
2. **GCM TimeSeries** (`-mode=gcm`): Queries Google Cloud Monitoring v3 `timeSeries.list` API with `view=FULL` over `[now - window, now]`.
3. **Both** (`-mode=both`): Verifies across both backends.

## Over-Time Assessment (`-window`)

For each of the 5 metric types (`GAUGE`, `COUNTER`, `HISTOGRAM (classic)`, `HISTOGRAM (native)`, `SUMMARY`), `verify-metrics` verifies over `-window` (default `5m`):
- **Series Count**: Exactly `1` active series (`-series-count=1`).
- **Sample Count**: At least `2` samples present within the window.
- **Value Semantics**:
  - `GAUGE`: values are within `[0, 100]` (`0 <= min <= max <= 100`).
  - `COUNTER`, `HISTOGRAM (classic)` (`_count`), `HISTOGRAM (native)` (`_count`), `SUMMARY` (`_count`): cumulative values increase over the window (`max > min`, `min >= 0`).

## Usage

```bash
# Verify all default acceptance scenarios via Makefile over a 5m window
make verify WINDOW=5m

# Verify a single scenario directly
go run ./tools/verify-metrics/main.go -bench-name=gmp -cluster-name=bwplotka-rw-acc -window=5m -mode=promql

# Verify against staging endpoint (auto-detected when -scenario is passed)
go run ./tools/verify-metrics/main.go -bench-name=prom-rw-m -scenario=./manifests/scenarios/prom-rw-m -cluster-name=bwplotka-rw-acc -window=5m
```

### Options

| Flag | Description | Default |
|------|-------------|---------|
| `-bench-name` | Scenario name (used as `namespace` label matcher) | `""` |
| `-avalanche-namespace` | Kubernetes namespace where shared `avalanche` runs | `"core"` |
| `-cluster-name` | GKE cluster name filter | `""` |
| `-project-id` | GCP project ID | Current gcloud project |
| `-window` | Time window over which to assess the 1 series data | `5m` |
| `-mode` | Query mode: `promql`, `gcm`, or `both` | `promql` |
| `-staging` | Use staging GCM endpoint (`staging-monitoring.sandbox.googleapis.com`) | Auto-detected from scenario, or `false` |
| `-promql-url` | PromQL query endpoint | GMP PromQL API URL (prod or staging) |
| `-token` | Bearer token for API | Auto-acquired via gcloud auth |
| `-load-manifest` | Path to avalanche manifest | `./manifests/core/3_avalanche.yaml` |
| `-format` | Output format (`table` or `json`) | `table` |
| `-concurrency` | Concurrent worker count | `4` |
| `-batch-size` | Metrics per batched PromQL query | `10` |
| `-max-retries` | Retries for throttled/transient failures (HTTP 429, 5xx) | `5` |
| `-timeout` | Overall verification timeout | `300s` |
